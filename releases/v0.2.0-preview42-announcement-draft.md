## 1. Ready-to-publish announcement draft

**Headline:** HorneroOS Public Preview — Signal Light & Night, Hornero Apps,
Universal Profiles, and Playground-ready Arch Workstations

HorneroOS is an Arch-based Wayland-first workstation family built for engineers,
creators, and gamers who want structured defaults, explicit provenance, and
clean reversibility without hidden magic.

Today's preview milestone brings together the **Hornero Signal** visual system
across the desktop, greeters, and web handbook, alongside our multi-source
**Hornero Apps** catalog, **Hornero Welcome** guided arrival, reversible
**Workspace Profiles & Snapshots**, and **Hornero Playground** tooling so new
visitors can evaluate HorneroOS safely before committing a drive.

### What this preview is—and what it is not

- **Used daily, honestly pre-release:** Desktop, Studio, and Gaming are
  **Preview** editions. Hyprland is our validated default compositor; Niri is
  experimental; Server and Agents remain planned editions without bootable
  images.
- **VM-validated ISO, growing hardware matrix:** Automated VM suites validate
  UEFI installs and Signal/Chromatic contrast sweeps. Physical-hardware
  certification across diverse laptops and GPUs is actively open for community
  reports.
- **No OS root rollback yet:** `horneroctl config snapshot` and
  `horneroctl profile` protect user configuration reversibly, while full OS
  snapshot rollback remains planned (`horneroctl recovery doctor` reports
  `none`).

### Try it safely

- **Already on Arch Linux (`x86_64`):** Install `hornero-shell`,
  `hornero-config`, `horneroctl-bin`, and optional `hornero-greeter` /
  `hornero-greeter-greetd` from the AUR without overwriting existing dotfiles.
- **Windows / Intel Mac / Linux VM:** Boot the verified ISO in QEMU/KVM
  (recommended, 60 FPS VirGL), VMware Workstation/Fusion, or VirtualBox (with 3D
  acceleration disabled).
- **Apple Silicon (`M1`–`M4`) note:** Builds are `x86_64` only today; UTM falls
  back to slow QEMU TCG CPU emulation. Use an `x86_64` host or self-host
  `HorneroOS/playground` on Linux `/dev/kvm` for real-time evaluation.

Start with the [Public Preview Launch Guide](../getting-started/public-preview-launch-guide.md)
and submit hardware findings via our **Hardware Compatibility Report** template.

## 2. Release highlights

- **Hornero Signal & Chromatic v3:** White-ceramic **Signal Day**, blue-hour
  **Signal Night**, **Signal Dusk**, **Signal High Contrast**, 24 curated themes
  (including Argentine Originals *Jacarandá*, *Glaciar*, and *Ceibo*), IBM Plex
  typography, and native C++ **Chromatic v3** dynamic palette synthesis.
- **Hornero Welcome (Signal Flight):** Guided first-run arrival (`First Flight`),
  everyday search (`Explore Hornero`), and upgrade highlights (`What's New`)
  with non-destructive live layout and theme previews.
- **Hornero Apps (`horneroctl store`):** Unified discovery across Arch repos,
  Flathub, AppImages, official vendor channels, isolated Web Apps, and opt-in
  AUR—every entry stamped with provenance (`Official`, `Verified`, `Community`,
  `Web App`), audit logging, and team policy controls.
- **Universal Profiles & Studio Routing:** Capture and switch 5 composable
  domains (`experience`, `audio`, `power`, `extensions`, `companion apps`) with
  a 15-second safety confirmation banner and reversible PipeWire live-call /
  DAW routing kits.
- **Hardened `horneroctl` & Dual Greeters:** Native V CLI with `horneroctl
  doctor`, `horneroctl store doctor`, `horneroctl recovery doctor`, bubblewrap
  agent confinement (`horneroctl agent run --sandbox`), and parity across SDDM
  (`hornero-greeter`) and `greetd` (`hornero-greeter-greetd`).
- **Playground & Demo Studio:** Ephemeral KVM + WebRTC self-host stack
  (`HorneroOS/playground`), VM launchers, and Presenter Mode for clean 1080p60
  walkthroughs.

## 3. YouTube demonstration checklist

Follow [YouTube and content production workflow](../studio/youtube-production-workflow.md)
for every launch walkthrough and clip:

- [ ] **Output geometry locked:** `1920×1080` at `60 FPS`, scale `1.0` (or
  `1080×1920` vertical for Shorts); confirm with `hyprctl monitors`.
- [ ] **Clean demo user & privacy hygiene:** Record in a clean demo VM or
  workstation overlay—no personal usernames, SSH keys, Wi-Fi SSIDs, LAN IPs,
  or tokens in terminal history or file listings.
- [ ] **Presenter Mode enabled & notifications silenced:**
  Run `qs ipc call notifs clear`, `hornero-presenter on` (or
  `qs ipc call notifs enableDnd`), and `horneroctl mode set studio`.
- [ ] **Mic & camera unarmed by default:** Keep `horneroctl hardware mic status`
  muted on silent B-roll takes; isolate Desktop (`Track 2`) and Mic (`Track 3`)
  in OBS MKV captures.
- [ ] **Must-show scenes covered:**
  1. `hornero-greeter` login & **Hornero Welcome** First Flight arrival.
  2. Live switch across **Signal Day**, **Signal Night**, **Signal High
     Contrast**, and **Chromatic v3**.
  3. **Hornero Apps** provenance badges (`Official` / `Verified` / `Web App`)
     and `horneroctl store profiles`.
  4. **Workspace Profiles** 15-second safety bar + Studio PipeWire routing kit.
  5. Honest limits slate: **Preview** editions, experimental **Niri**,
     `x86_64`-only Apple Silicon caveat, and planned OS rollback.
- [ ] **Post-production & accessibility deliverables:** Export editable
  `.kdenlive` bundle, `chapters.txt` (`>= 10 s` spacing starting at `00:00`),
  `subtitles.en.srt` + `subtitles.es.srt`, and crisp PNG thumbnails via
  `horneroctl capture screenshot`.
- [ ] **Teardown after take:** Run `hornero-presenter off` and restore your
  mode with `horneroctl mode set signal`.
